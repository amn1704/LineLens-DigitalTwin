# LineLens Prototype Assumptions

## Purpose
LineLens is built as an interactive software prototype for the Accenture Innovation Challenge 2026. It is designed to demonstrate methodology, architecture, user experience, and engineering approach for an automotive digital twin. It is **not** a production-ready application calibrated for real-world deployment.

## Synthetic Factory Data
All telemetry, sensor readings, process variations, and vehicle builds are generated by a fast, in-memory synthetic simulator. LineLens does not use real plant telemetry, nor does it connect to live programmable logic controllers (PLCs) or manufacturing execution systems (MES).

## Station Topology
The factory model uses 11 representative stations across three shops (Body Shop, Paint Shop, Final Assembly). This is a simplified linear topology. Real automotive plants have hundreds of stations, complex parallel lines, rework loops, and non-linear buffers.

## Sensor Maturity
The prototype assigns fixed "sensor maturity" tiers (Full, Limited, Basic) to specific stations to demonstrate capability across varying data quality. In a real factory, sensor coverage is discovered dynamically and changes over time.

## Simulation Simplifications
The entire stack runs in-memory and is single-threaded. There is no persistent database. Restarting the backend resets all baseline history, vehicle threads, and validation metrics. Physical physics (kinematics, exact fluid dynamics for paint, etc.) are simplified into time and capacity math.

## Prediction Model
The bottleneck prediction uses an interpretable weighted logistic model calibrated specifically for the prototype's synthetic scenarios. Thresholds and weights were tuned to trigger reliably during a short demonstration. It is not trained on real-world factory failure labels.

## Quality Model
The vehicle quality model identifies synthetic defects using a simulated logistic regression artifact. The "defect families" and process parameters (like weld energy deviation or torque variance) are representative concepts, not actual metallurgical or mechanical inspection data.

## Confidence Model
The confidence percentages (e.g., 85% twin state confidence) are bounded heuristic indicators combining freshness, maturity, and stability. They represent qualitative trust for the user interface, not rigorously calibrated statistical probability intervals.

## Forward Twin
The disposable "no-intervention" forecast is a fast deterministic clone of the current Twin state. It relies on seeded randomness and ignores stochastic variation. It projects standard outcomes but does not simulate complex emergent plant chaos.

## Incident Engine
The Incident Engine manages human workflow state (Acknowledge, Investigate, Resolve). It never writes commands back to the simulator, stops machines, or executes autonomous control actions. The boundary is strict decision support.

## Scale
The architecture is designed to cleanly separate observation from prediction, which supports scaling. However, this repository runs a contained 11-station model. Performance at a 300-station scale with high-frequency telemetry has not been benchmarked.

## Decision Support Boundary
LineLens synthesizes data into evidence, forecasts impacts, and recommends actions. The core philosophy is that humans make the final decisions. The prototype deliberately excludes Reinforcement Learning (RL), Proximal Policy Optimization (PPO), or autonomous line intervention.
